subs2dub

Turn an existing subtitle track into a synced dub.

Runs locally. No API keys, no account, no per-character billing.

Most dubbing pipelines transcribe the source with Whisper and machine-translate it. If you already have good subtitles, that throws away the best asset you have — a human translation. subs2dub treats the subtitle file as the script.

The hard part is timing

A subtitle cue is a fixed window. Synthesized speech is whatever length it happens to be. Everything else follows from reconciling those two facts.

Four levers, applied in order of how much they degrade the audio: leave it alone, borrow silence from the following gap, re-synthesize faster, then pitch-preserving time-stretch — capped, because past ~15% it audibly wobbles.

Roughly three quarters of lines need no manipulation at all, and speech starts within about 35 ms of the cue start. Lines that still overrun are reported rather than degraded further — they have more syllables than the window allows, which is a writing problem, not an audio one.

What else it does

  • Removes the original dialogue instead of ducking it, so the dub isn't competing with the source language
  • Works out who speaks each line and gives each character a distinct voice
  • Optionally clones each character from the original performer while keeping native pronunciation
  • Copies each actor's delivery — loudness, emphasis, question intonation
  • Keeps the original audio as a second track, so the result is still watchable in the source language

Install

# macOS
brew install ffmpeg rubberband espeak-ng

git clone https://github.com/prvrtl/subs2dub.git
cd subs2dub
./scripts/setup.sh

Python 3.10 or 3.11. Model weights (~4 GB) download on first run and are cached. Needs about 8 GB free disk.

Use

# 90-second preview — use this while tuning
python -m subs2dub build movie.mkv -o preview.mkv --clip 60:90

# the whole film, in the original cast's voices
python -m subs2dub build movie.mkv -o dubbed.mkv \
    --backend chatterbox --voice-convert

Subtitles are pulled out of the container automatically. Renders are cached, so an interrupted job resumes where it stopped.

Pick your tradeoff

Native pronunciation, the original actor's voice, and expressive delivery trade against render time. Figures are for a two-hour film on an M1 Pro.

ConfigurationNativeActorEmotionTime
kokoroyesnono~8 min
chatterboxaccentyesyes~6 h
kokoro + convertyesyesno~30 min
chatterbox + convertyesyesyes~7.5 h

The last row is the best quality available locally. Expressive models are roughly 60× slower than the fast one — that's inherent, not a tuning problem.

Cloning without conversion inherits the source language's accent, because the model conditions on the whole acoustic style of the reference clip. Conversion fixes it by synthesizing native speech first and transferring only the tone colour.

What it doesn't do well

  • Phone calls, shouting and whispering can split one character into two
  • Characters with very few lines may be merged into others
  • Singing and crowd noise are removed by separation and don't come back; musical numbers play with original audio and no dub
  • Lip sync is approximate — phoneme-accurate sync needs a video model
  • Emotion is derived from how loudly a line was delivered, which captures arousal but not valence: it can't tell frightened from furious
  • OCR artifacts in the source subtitles get pronounced literally
